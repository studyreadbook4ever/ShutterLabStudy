# 물리·카메라 모델

## 운동과 단위

한 물체가 고정 회전축을 중심으로 회전하며 토크와 선형 점성 감쇠를 받습니다. 물체의 병진 운동·충돌·축 이동은 포함하지 않습니다. 관성은 형상과 별도로 지정하는 유효 회전 관성입니다. 물체 선택 시 권장 초기값을 적용하지만 형상·질량으로 자동 계산하지는 않으며 이후 자유롭게 조절할 수 있습니다.

```text
I · dω/dt = τ − bω
dθ/dt = ω
```

| 기호 | 의미 | 내부 단위 |
| --- | --- | --- |
| θ | 회전각 | rad |
| ω | 각속도 | rad/s |
| τ | 토크 | N·m |
| I | 회전 관성 | kg·m² |
| b | 점성 감쇠 계수 | N·m·s/rad |
| t | 시간 | s |

UI의 rpm은 `ω = rpm·2π/60`, ms는 `t = ms/1000`으로 변환합니다. 운동 에너지는 `E = Iω²/2`입니다.

상수 τ, I, b에 대해 해석적으로 적분합니다. `b = 0`인 경우:

```text
ω(t) = ω₀ + (τ/I)t
θ(t) = θ₀ + ω₀t + (τ/2I)t²
```

`b > 0`일 때 `β = b/I`, `ω∞ = τ/b`로 두면:

```text
ω(t) = ω∞ + (ω₀ − ω∞)exp(−βt)
θ(t) = θ₀ + ω∞t + (ω₀ − ω∞)(1 − exp(−βt))/β
```

JavaScript 모델은 작은 감쇠에서 상쇄 오차가 커지지 않도록 `expm1`과 급수 전개를 사용합니다. 각도를 누적한 상태로 보관하며 프레임 중심보다 이른 노출을 평가하기 위한 음수 시간도 지원합니다. 고정 τ, I, b 조건에서 적분을 나누어 적용해도 같은 상태가 됩니다.

## 셔터 시간

상태 `(θ₀, ω₀)`는 **센서 판독과 노출의 중앙 시각**에 정의합니다. 행 번호 r은 화면 위에서 아래로 0부터 증가하고, 높이는 H입니다. 방향 d는 위→아래일 때 +1, 아래→위일 때 −1입니다.

```text
Rolling 행 시각 = d·Tscan·((r + 0.5)/H − 0.5)
Global 행 시각  = 0
노출 샘플 시각  = 행 시각 + Texposure·((k + 0.5)/N − 0.5)
```

k는 0부터 N−1까지의 시간 샘플 번호입니다. 두 셔터는 같은 노출 샘플을 사용하며 중앙점 구적법으로 노출 구간을 근사합니다. `Tscan`은 센서 높이 전체에 해당하는 판독 시간입니다. 첫 행 중심과 마지막 행 중심 사이의 간격은 `Tscan·(H−1)/H`입니다.

전체 센서 판독을 0으로 설정하면 두 셔터의 시간식이 같습니다. 물체가 정지하고 토크도 0이면 행 시각을 바꿔도 자세가 같습니다. 방향을 뒤집으면 판독 순서만 반대가 되고 노출 내부의 누적 시간은 유지됩니다. 실제 센서의 행별 순차 노출에 관한 배경은 [Basler의 셔터 설명](https://docs.baslerweb.com/electronic-shutter-types)을 참고하세요.

## 카메라 광선

카메라 원점은 `(0, 0, 5.8 m)`이며 −z 방향을 봅니다. 배경 격자 평면은 `z = −2.2 m`입니다. 주점은 영상 중심이고 FOV는 **수평 시야각**입니다. 아래 식의 x는 영상 중심 기준 정규화한 가로 좌표이고, y는 같은 수평 척도로 표현한 세로 좌표입니다. 화면의 위쪽은 +y입니다. α는 수평 시야각의 절반입니다.

Pinhole의 광선 방향:

```text
ray = normalize(x·tan α, y·tan α, −1)
```

이는 rectilinear 투영 `r = f·tan θ`의 역투영입니다. 장면의 직선이 직선으로 보이지만 큰 시야각에서 주변부가 늘어납니다.

Equidistant Fisheye의 광선은 `ρ = √(x²+y²)`, `γ = αρ`일 때:

```text
ray = (sin γ·x/ρ, sin γ·y/ρ, −cos γ)
ρ = 0이면 ray = (0, 0, −1)
```

이는 `r = f·θ` 투영입니다. 이 프로젝트는 이상적인 등거리 모델을 사용합니다. OpenCV의 fisheye 모델은 각도에 다항 보정 계수를 적용하므로 실제 렌즈 보정으로 확장할 때 참고할 수 있습니다. [OpenCV 공식 문서](https://docs.opencv.org/4.x/db/d58/group__calib3d__fisheye.html)

고정 배경과 움직이는 물체가 같은 카메라 광선을 사용합니다. 따라서 고정 격자의 휘어짐은 공간 투영의 효과이며, 움직이는 형상의 행별 차이는 셔터 시각의 효과입니다. 광축을 지나는 직선은 방사형 투영에서도 곧게 남을 수 있어 중심 오프셋이 유용한 실험 변수입니다.

## 렌더링과 지표

각 픽셀에서 카메라 광선을 만들고 그 샘플 시각의 물체 자세에 대해 교차점을 계산합니다. 여러 시간 샘플의 색을 누적합니다. CUDA 렌더러는 시간 샘플마다 공간 서브픽셀 광선도 추적하고 선형 색 공간에서 평균한 다음 sRGB로 인코딩합니다.

WebGL2는 fragment shader에서 같은 운동·카메라·노출 정의를 평가합니다. 수치 정밀도, 공간 샘플링과 조명 근사는 CUDA와 다를 수 있습니다. 백엔드 간 이미지 차이를 셔터 차이로 해석하면 안 됩니다. 비교 화면은 항상 같은 백엔드의 두 셔터를 보여 줍니다.

| 표시 | 의미 |
| --- | --- |
| 읽기 중 회전 | 판독 구간 양 끝의 모델 회전각 차이의 절댓값 |
| 노출 중 회전 | 노출 구간 양 끝의 모델 회전각 차이의 절댓값 |
| 운동 에너지 | `Iω²/2`, 현재 각속도 기준 |
| RGB MAE | 두 프레임의 RGB 절대 차이 평균, 범위 0–255 |
| CUDA 시간 | CUDA event로 측정한 커널 실행 시간 |
| 브라우저 렌더 시간 | 렌더링 완료까지 측정한 경과 시간 |
| 화면 fps | 브라우저의 영상 갱신 빈도 |

각도 변화는 각속도와 토크·감쇠를 포함한 현재 상태에서 계산합니다. 일정 속도라면 `|ω|·T`이며 120 rpm, 22 ms 판독은 15.84°입니다. 픽셀 차이는 렌즈·깊이·형상·자세도 반영하므로 각도 변화와 같은 값이 아닙니다. 서로 다른 백엔드의 렌더 시간을 직접적인 CUDA/WebGL 속도비로 해석하지 않습니다.

이 모델은 학습용입니다. 렌즈 수차·실제 보정 계수·센서 노이즈·회절·광학 PSF·충돌·임의 메시·형상에서 유도한 관성은 포함하지 않습니다. 유한한 시간 샘플링은 매우 빠른 운동에서 temporal aliasing을 만들 수 있습니다.
